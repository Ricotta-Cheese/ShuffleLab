# Shuffle Lab

배열 셔플 알고리즘의 **효율성**, **관계성**, **균등성**을 비교하고 내부 동작을 시각화하는 교육용 웹앱입니다.
2026학년도 2학기 알고리즘 과제(주제 A: 알고리즘 동작 시각화)로 만들고 있습니다.

> 정렬 알고리즘은 다양하게 배우지만, 배열을 무작위로 섞는 알고리즘은 왜 잘 배우지 않을까?
> 섞는 알고리즘에도 종류가 있다면, 효율성과 무작위성에는 어떤 차이가 있을까?

- 저장소: [Ricotta-Cheese/ShuffleLab](https://github.com/Ricotta-Cheese/ShuffleLab)
- 배포 설정: Vercel용 빌드 및 SPA 경로 재작성 설정 포함 (`vercel.json`)

## 비교하는 알고리즘

| 알고리즘 | 시간 | 추가 공간 | 균등한 셔플 | 비교 목적 |
|---|---|---|---|---|
| Fisher–Yates | O(n) | O(1) | 예 | 기준 알고리즘 |
| Random Pick & Remove | O(n²) | O(n) | 예 | 균등한 셔플끼리의 효율성 비교 |
| Riffle Shuffle (7회) | O(n) | O(n) | 근사적으로 (TVD < 0.01, n ≤ 5) | 같은 O(n)인데 균등성이 다른 실제 카드 섞기 모델 |
| Random-Key Sort | O(n log n) | O(n) | 키가 모두 다를 때만 | 정렬을 이용한 셔플 |

- **Fisher–Yates**: 맨 뒤 칸부터 `0..i` 범위에서 하나를 골라 i번 칸과 바꾸고, 그 칸을 확정합니다.
- **Random Pick & Remove**: 남은 원소 중 하나를 골라 결과 배열에 붙이고 원래 배열에서 지웁니다. 지울 때마다 뒤쪽 원소를 당겨야 해서 O(n²)입니다.
- **Riffle Shuffle**: 동전 n번의 결과로 더미를 자르는 위치와 끼워 넣는 순서를 정하는 Gilbert–Shannon–Reeds 리플을 7번 반복합니다. n ≥ 3에서는 경로 2^(7n)개를 n!개 순열에 똑같이 나눌 수조차 없고, n = 2에서도 원래 순서가 조금 더 자주 나와 정확히 균등하지 않습니다. 작은 배열에서는 편향이 작지만, 배열 크기에 따라 달라집니다. 정확한 확률은 상승 수열 공식(Bayer–Diaconis)으로 구합니다.
- **Random-Key Sort**: 원소마다 [0, 1) 난수 키를 붙이고 키 순으로 정렬합니다. 실제 실수는 정밀도가 유한해서 키가 같을 수 있고, 이때 안정 정렬이 원래 순서를 유지하면 편향이 생깁니다.

## 분석 지표

| 관점 | 지표 | 설명 |
|---|---|---|
| 관계성 | Kendall's τ, R = \|τ\| | 원본과 결과 사이에서 원소 쌍의 앞뒤 순서가 얼마나 유지되는지 |
| 균등성 | TVD, U = 1 − TVD | 반복 실험으로 얻은 순열 분포가 균등분포(1/n!)와 얼마나 다른지 |
| 효율성 | 실행 시간, 연산 횟수 | 입력 크기별 실행 시간(반복 측정)과 교환·읽기·쓰기·이동 횟수 |

- R은 원본 순서와의 관계를 나타낼 뿐, **무작위성 점수가 아닙니다.** 올바른 셔플도 한 번 실행하면 R이 높게 나올 수 있습니다.
- U는 이 프로젝트에서 정의한 표시용 지수입니다. 실험 횟수가 유한하면 올바른 알고리즘도 정확히 1이 되지 않으므로, 배열 크기·반복 횟수와 함께 해석합니다.
- 균등성 실험은 통계적 균등성을 관찰하는 것이지, 난수 생성기의 암호학적 안전성을 검증하는 것이 아닙니다.

## 실험과 결과 비교

### 난수와 이론값

- C·D는 시드 고정 난수를 사용합니다. E·F에서는 시드 고정(SFC32), `Math.random`, `crypto.getRandomValues` 중에서 선택합니다.
- D의 τ 분포는 같은 입력을 2,000번 섞어 계산합니다. 단일 결과와 난수 수열을 분리하기 위해 분포 계산에는 입력 시드에 1,000,003을 더한 시드를 씁니다.
- E는 알고리즘마다 별도 Worker에서 반복 실험을 실행하며, 진행률 표시와 취소를 지원합니다.
- Fisher–Yates와 Pick & Remove의 이론 분포는 난수 선택 경로를 열거하고, Riffle은 상승 수열 공식으로 계산합니다. Random-Key Sort의 이론선은 **독립적인 키가 모두 다르다는 가정**의 균등분포입니다. 유한 정밀도 키의 충돌 편향을 계산한 값은 아닙니다.

### 효율성 측정 (실행 시간)

- F는 배열 크기를 2^8(256)부터 두 배씩 늘립니다. 최대 크기는 2^14·2^16·2^18·2^20 중에서, 측정 횟수는 5·9·15회 중에서 선택합니다.
- 알고리즘끼리 동시에 CPU를 사용하지 않도록 Worker 하나에서 순서대로 측정합니다.
- 입력 배열 생성·복사는 측정 구간에서 제외하고, 셔플 내부의 난수 생성과 메모리 할당은 포함합니다. 단계 기록용 `trace`는 사용하지 않습니다.
- 워밍업 후 짧은 실행을 배치로 묶어 측정하고, 셔플 1회당 시간의 중앙값·최솟값·최댓값을 구합니다. 배치 크기는 기본 5ms 목표와 총 원소 수 상한을 기준으로 조절합니다.
- 한 크기에서 중앙값이 200ms를 넘으면 해당 알고리즘의 더 큰 크기는 건너뜁니다. 측정 중 탭이 숨겨진 경우에도 안내를 표시합니다.

### 전체 비교와 저장

G의 **모두 측정**은 다음 조건으로 관계성 → 균등성 → 효율성 순서로 실행합니다. 균등성 실험이 끝난 뒤 실행 시간 측정을 시작합니다.

| 관점 | 표준 조건 |
|---|---|
| 관계성 | 원소 8개, 2,000회 반복, 기준 시드 1 |
| 균등성 | 원소 4개, 1,000,000회, 시드 고정 난수·시드 1 |
| 효율성 | 크기 2^8~2^14, 크기별 5회 측정, 시드 고정 난수·시드 1 |

각 알고리즘의 최신 결과는 `localStorage`에 저장합니다. 저장소를 사용할 수 없으면 현재 방문 동안만 유지합니다. 관계성은 반복 분포의 요약, 균등성은 완료된 알고리즘의 결과, 효율성은 측정 작업이 끝까지 완료된 결과만 기록합니다. 취소·오류로 중단된 효율성 측정은 저장하지 않습니다. G에서는 측정 조건 차이를 안내하고, 실행 시간은 측정된 알고리즘들이 공통으로 가진 가장 큰 배열 크기에서 비교합니다. 저장 결과는 G의 **결과 지우기** 버튼으로 지울 수 있습니다.

## 구현 원칙

- **난수 분리**: 알고리즘은 `Rng` 인터페이스로만 난수를 얻습니다. 시드 고정 의사난수(SFC32), `Math.random`, `crypto.getRandomValues` 중에서 고를 수 있습니다. 정수 난수는 거부 샘플링으로 모듈로 편향을 없앴습니다.
- **두 가지 버전**: 알고리즘마다 빠른 버전 `shuffle`과 기록 버전 `trace`를 따로 둡니다.
  - `shuffle`은 성능 측정과 반복 실험에 씁니다.
  - `trace`는 단계별 배열 상태, 선택 위치, 누적 연산 횟수, "무엇을 / 왜" 설명을 남깁니다.
  - 같은 시드에서 두 결과가 같은지 테스트로 확인합니다.
- **정확한 이론 분포**: `exactDistribution`은 작은 n에서 난수 선택 경로를 모두 따라가 순열별 정확한 확률을 구합니다. 실험 결과와 비교할 이론값으로 씁니다. 경로가 너무 많은 Riffle은 상승 수열 공식 `riffleProbability`를 씁니다.

## 시작하기

Node.js **24**를 권장합니다. 현재 사용하는 Vite와 Vitest의 Node.js 요구 범위를 모두 만족하는 버전입니다.
아래 명령은 저장소 루트(`package.json`이 있는 폴더)에서 실행합니다.

```bash
npm ci             # package-lock.json 기준 설치
npm run dev        # 개발 서버 (http://localhost:5173)
npm test           # 단위 테스트
npm run test:watch # 테스트 감시 모드
npm run typecheck  # TypeScript 타입 검사
npm run build      # 타입 검사 + 프로덕션 빌드
npm run lint       # oxlint
npm run preview    # dist 빌드 결과 로컬 미리보기 (빌드 후 실행)
```

빌드 결과는 `dist/`에 생성됩니다. Vercel의 Root Directory는 기본값(저장소 루트)을 그대로 씁니다. `vercel.json`은 `npm run build`, 출력 폴더 `dist`, React Router의 하위 경로 직접 접근을 위한 `index.html` 재작성을 설정합니다.

## 검증

`npm test`로 다음을 확인합니다.

- 모든 알고리즘의 결과가 원본의 순열인지 확인합니다(중복·손실 없음, n = 0~12).
- 같은 시드에서 `shuffle`과 `trace`의 결과가 같은지 확인합니다.
- Fisher–Yates의 j가 항상 `0 ≤ j ≤ i` 범위인지 확인합니다.
- Fisher–Yates와 Pick & Remove는 n = 1~5에서 모든 순열의 정확한 확률이 1/n!인지 확인합니다.
- Riffle Shuffle
  - 리플 1~3번에서 경로를 모두 열거한 분포가 상승 수열 공식과 같은지 확인합니다(n = 3~5).
  - 리플 한 번은 두 더미의 순서를 유지하는지(상승 수열 2개 이하) 확인합니다.
  - 리플 7번에서 확률의 합이 1이고, 정확히 균등하지는 않은지 확인합니다(n = 2~6).
- Random-Key Sort
  - 키 순서대로 정렬되는지 확인합니다.
  - 같은 키가 있으면 원래 순서를 유지하고, 그 사실을 단계 설명에 표시하는지 확인합니다.
- 정수 난수의 거부 샘플링, 시드 재현성, 난수 범위를 확인합니다.
- Kendall's τ의 일치·역순·중간 사례와 중복·잘못된 순열 입력 거부를 확인합니다.
- 순열 번호와 순열의 상호 변환, TVD·U의 계산, 알고리즘별 이론 확률의 합과 이론 TVD를 확인합니다.
- 반복 실험의 집계 합계·진행 알림과 시드 고정 실험 결과를 확인합니다.
- 반복 관계성 계산의 평균·비율과 τ 콜백을 확인합니다.
- 벤치마크의 배치 상한, 가짜 시계를 통한 1회당 시간 계산, 중앙값과 크기 두 배 증가 비율을 확인합니다.

현재 단위 테스트는 `core`의 계산 로직을 대상으로 합니다. 브라우저 화면과 Worker 연동은 단위 테스트 범위에 포함되지 않습니다.
